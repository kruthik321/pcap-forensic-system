Abstract

Digital Network Forensics plays a vital role in cyber incident response by preserving, reconstructing, and analyzing low-level packet communications. However, manual examination of Packet Capture (PCAP/PCAPNG) files using conventional tools such as Wireshark is time-consuming, requires high expertise, and is inefficient for rapid triage. Furthermore, contemporary automated forensic platforms suffer from severe memory bottlenecks due to in-memory packet caching and lack persistent queryable indexing or standardized digital forensic serialization.

This project designs and implements the Automated PCAP Forensic Analysis and Reporting System, an end-to-end digital forensic solution that bridges raw packet evidence with explainable incident reports. The system ingests raw PCAP/PCAPNG files, computes cryptographic hashes (SHA-256) to ensure legal Chain of Custody (CoC) compliance under NIST SP 800-86 standards, and parses packets using a hybrid dissection engine (PyShark / Tshark with a resilient Scapy fallback).

To overcome the architectural shortcomings of recent research benchmarks (such as NetForensics, IJACSA 2026), the system implements a Dual Storage Architecture:

  • Relational SQLite Database (packets.db): High-speed indexed tables for packets, aggregated network flows, and forensic alerts, enabling custom ad-hoc SQL forensic queries.
  • Standardized Forensic XML (evidence.xml): RFC/PDML-compatible hierarchical serialization for cross-tool interchange.

The system incorporates a rule-based Multi-Vector Threat Detection Engine capable of detecting reconnaissance port scans (SYN/FIN stealth scans), Denial of Service (TCP SYN floods), plain-text credential harvesting (HTTP/FTP/Telnet), application-layer web exploits (SQL Injection, Cross-Site Scripting, Directory Traversal), and DNS data exfiltration/tunneling. Finally, the system generates comprehensive investigative reports in HTML, Markdown, PDF, and CSV formats, coupled with an interactive web dashboard for real-time visualization.

1. Introduction and Problem Statement

1.1 Background & Motivation

In modern enterprise and campus networks, cyber threats frequently bypass perimeter defenses. While host logs can be cleared or altered by malicious actors, raw packet capture (PCAP) data preserves unalterable network truth. Capture files contain packet arrival timestamps, protocol headers, TCP control flags, and raw payloads. Despite their value, PCAPs are challenging to investigate manually: files often contain tens of thousands of packets, requiring laborious protocol filter construction in Wireshark.

1.2 Problem Statement

Existing tools are either complex packet sniffers without automated reporting (Wireshark) or enterprise IDS engines that discard raw packet evidence (Suricata/Snort). Recent academic prototypes (e.g., NetForensics, IJACSA 2026) suffer from memory bottlenecks by storing captures in volatile RAM and export only flat JSON/CSV files without relational database querying capabilities.

1.3 Objectives

  • Objective 1: Automatically extract and analyze Layer 2–7 information from PCAP files using PyShark and Scapy.
  • Objective 2: Convert extracted PCAP data into RFC-compatible XML and store structured records in an indexed SQLite database.
  • Objective 3: Identify suspicious traffic patterns (Port Scans, SYN Floods, Web Attacks, DNS Tunneling, Credential Leaks).
  • Objective 4: Generate comprehensive forensic reports in HTML, Markdown, PDF, and CSV formats with interactive SQL queries.

4. Implementation Details

4.1 Database Schema (SQLite 3)

The relational database stores granular dissections, aggregated flows, and evidence metadata with multi-column indexes: 

CREATE TABLE packets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    packet_num INTEGER,
    timestamp TEXT,
    src_ip TEXT,
    dst_ip TEXT,
    protocol TEXT,
    src_port INTEGER,
    dst_port INTEGER,
    length INTEGER,
    tcp_flags TEXT,
    payload_preview TEXT,
    info TEXT
);

CREATE INDEX idx_src_ip ON packets (src_ip);
CREATE INDEX idx_dst_ip ON packets (dst_ip);
CREATE INDEX idx_protocol ON packets (protocol);
CREATE INDEX idx_timestamp ON packets (timestamp);
CREATE INDEX idx_dst_port ON packets (dst_port);

4.2 Algorithmic Threat Detection Signatures

  • Port Scan Rule: Triggers when distinct destination ports probed by a source IP $\ge 10$. Classifies SYN stealth scans (SYN flag set without ACK) and FIN scans.
  • DoS / SYN Flood Rule: Triggers when incomplete SYN handshake packets exceed threshold ($> 40$) without session completion.
  • Cleartext Credential Hunter: Regex search across packet payloads for password=, pwd=, and Authorization: Basic.
  • SQL Injection Signature: (\bUNION\b.*\bSELECT\b|'\s*OR\s*['\d]=['\d]|--|/\*|\bWAITFOR\s+DELAY\b)
  • Cross-Site Scripting (XSS): (<script.*?>|%3Cscript.*?%3E|javascript:|onerror\s*=|onload\s*=)
  • DNS Tunneling: Flags DNS queries exceeding 60 characters or displaying elevated character entropy.

6. Forensic Integrity & Chain of Custody (NIST SP 800-86)

The system adheres strictly to digital forensic principles:

  1. Non-Destructive Ingestion: The source capture is treated as an immutable byte stream and never modified.
  2. Cryptographic Digest: Computes SHA-256 checksum at ingestion. The resulting 64-character hash is recorded across the SQLite metadata table, XML header, and report summaries.
  3. Evidence Traceability: Every alert contains direct packet reference numbers pointing back to the source packet within the capture.

The Automated PCAP Forensic Analysis and Reporting System delivers a functional, academically rigorous platform fulfilling all requirements of the Information Security Laboratory curriculum. By combining PyShark dissection, SQLite relational indexing, and RFC-compliant XML serialization, the system provides a significant architectural upgrade over in-memory tools like NetForensics.
